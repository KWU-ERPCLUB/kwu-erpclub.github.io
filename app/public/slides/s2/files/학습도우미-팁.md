## 2. 퀴즈를 만들 때 주의점

| 문제 | 왜 생기나 | 규칙으로 막는 법 |
|---|---|---|
| 자료에 없는 내용이 문제로 나온다 | AI가 자기 지식을 섞는다 | 문항마다 출처(슬라이드 번호·페이지)를 달게 하고, 출처 없는 문항은 버린다 |
| 암기 문제만 나온다 | 자동 출제는 단순 암기로 쏠린다 | "개념 문제 3 + 응용 문제 2"처럼 비율을 규칙에 적는다 |
| 정답이 한 자리에 몰린다 | 모델마다 정답 위치 버릇이 있다 | "정답 위치를 골고루 섞어라" + 채점 때 정답 번호 분포를 확인한다 |
| 오답 보기가 너무 뻔하다 | 생성된 오답 보기 중 바로 쓸 만한 것은 절반 수준 | "헷갈리기 쉬운 개념으로 오답 보기를 만들어라" |
| 정답이 틀렸다 | 같은 모델은 자기 실수를 잘 못 본다 | 다른 모델에 퀴즈를 붙여 넣어 정답을 확인한다 |
| 틀린 보기를 사실로 기억한다 | 객관식의 부작용 | 틀린 문항은 해설을 반드시 읽는다. `/grade`이 해설을 쓰게 한다 |
| 과목 성격과 안 맞는 문제 | 시험 형태를 모른다 | `과목정보.md`의 시험 유형을 퀴즈 형식에 반영한다 (예: 인터넷활용 = 코드 오류 찾기) |

## 3. 하네스를 만들 때 참조할 것

university 오류 기록과 운영자 하네스 감량 경험에서 나온 것만 적는다.

1. **스킬 호출어가 겹치지 않게 한다.** university에서 "소스 만들어줘"가 엉뚱한 스킬을 불렀다
2. **하지 말아야 할 것은 명시한다.** "명령만 출력"이라고만 적었더니 AI가 매번 폴더부터 뒤져 느려졌다. "사전 확인 금지"를 적고 나서 고쳐졌다
3. **과목마다 다른 것은 과목 폴더에 둔다.** 공통 규칙과 과목 규칙을 섞으면 다른 과목 결과가 오염된다
4. **경로를 박지 않는다.** 내 컴퓨터 경로를 적으면 다른 기기와 다른 사람 폴더에서 안 돈다
5. **실패는 기록하고 규칙 한 줄로 흡수한다.** 같은 실수가 두 번 나오면 규칙을 고칠 때다
6. **두 번 이상 반복한 일만 스킬로 만든다.** 한 번 한 일을 스킬로 만들면 관리할 것만 는다
7. **규칙은 주기적으로 줄인다.** "지우면 AI가 실수하나?"를 물어 아니면 지운다. 운영자 하네스는 이 방식으로 상시 규칙을 335줄에서 123줄로 줄였다
8. **가장 단순한 것부터 시작한다.** 스크립트·자동 실행 규칙은 필요해질 때 붙인다

## 4. 이미 하네스가 있는 사람: 점검 6항목

| 항목 | 확인 방법 |
|---|---|
| 불필요한 규칙 | 한 줄씩 "지우면 AI가 실수하나?" 아니면 삭제 |
| 중복·충돌 | 같은 규칙이 여러 파일에 있는지, 스킬 호출어가 겹치는지 |
| 화석 | 안 쓰는 스킬, 옛 경로, 폐기된 기능 |
| 길이 | 항상 읽히는 파일은 짧게, 상세는 필요할 때 읽는 문서로 |
| 이식성 | `CLAUDE.md` 전용 규칙을 `AGENTS.md`로 옮기고 불러오기 |
| 기록 고리 | 실패가 규칙 수정으로 이어지는 통로가 있는지 |

점검 결과는 항목마다 유지 · 삭제 · 통합 · 이동 중 하나로 표시하고, 바꾼 것을 목록으로 남긴다.

# 발주서 C · 공고 탭 점검 에이전트

AIM 허브 워크스페이스 「공고」 탭의 데이터를 매주 점검할 에이전트를 발주한다. 받는 것은 완성된 에이전트 하나다. 만드는 방법은 자유다.

## 1. 배경

2026-10-24 기준 허브 「공고」 탭 36건 중 27건은 마감이 지났다. 8건은 마감일이 비어 있다. 점검을 맡은 사람이 없어서 생긴 일이다.

이 에이전트는 공고 탭 데이터를 읽고 결함을 찾아 정리안을 낸다. 운영진은 정리안을 보고 데이터를 고친다. 합격 기준을 통과하면 운영진이 매주 자동 실행에 넣는다.

## 2. 하는 일

| 번호 | 요구 |
|---|---|
| F1 | 공고 탭 데이터(JSON 배열: 공고 한 건을 중괄호로 묶어 여러 건을 늘어놓은 데이터. `null`은 값이 없다는 표시)와 기준일을 받아 행마다 3절 결함을 전부 찾는다 |
| F2 | 결함마다 그 행의 값을 근거로 남기고 정해진 조치를 붙인다 |
| F3 | 결함이 없는 행 수를 센다 |
| F4 | 실행할 때마다 4-2 ② 실행 보고를 쓴다 |

## 3. 결함 기준

기준의 내용은 바꿀 수 없다. 표현은 본인 에이전트에 맞게 다시 써도 된다.

| 코드 | 결함 | 판정 | 확신 | 조치 |
|---|---|---|---|---|
| D1 | 마감 경과 | 접수마감이 기준일보다 앞선 날짜 | 확실 | `보관` |
| D2 | 마감일 없음 | 접수마감 `null` · 종류가 교내활동이 아님 · 제목에 「상시」 없음(셋 다 해당) | 확실 | `원문에서 마감일 확인` |
| D3 | 값 목록 밖 | 종류나 분류가 4-1 값 목록에 없음 | 확실 | `값 목록에서 다시 고름` |
| D4 | 날짜 모양 | 접수시작이나 접수마감이 `null`도 아니고 `YYYY-MM-DD` 모양도 아님(빈 문자열 포함) | 확실 | `YYYY-MM-DD로 고침` |
| D5 | 날짜 모순 | 접수시작과 접수마감이 둘 다 날짜인데 시작이 마감보다 뒤 | 확실 | `원문에서 기간 확인` |
| D6 | 키 중복 | 같은 키가 2행 이상. 그 키의 모든 행에 붙인다 | 확실 | `하나만 남김(운영진 판단)` |
| D7 | 링크 모양 | url이 `https://`로 시작하지 않음(`javascript:` 포함) | 확실 | `원문 링크 다시 확인` |
| D8 | 종류 오분류 | 제목은 채용 공고로 보이는데 종류가 `채용`이 아니거나, 제목은 공모전으로 보이는데 종류가 `공모전`이 아님. 교내활동 행은 보지 않는다 | 의심 | `종류 확인` |
| D9 | 같은 공고 | 키는 다른데 url이 같은 행(그 행들 모두에 붙인다) | 확실 | `하나만 남김(운영진 판단)` |

- 한 행에 결함이 여러 개면 전부 적는다
- D8은 제목만 보고 하는 판단이라 항상 「의심」이다. 제목에 근거가 되는 말(예: 「인턴」 「경진대회」)을 근거 칸에 옮긴다
- **입력 오류**: 배열이 끝까지 오지 않았거나(마지막 행이 잘림 · 괄호 짝이 맞지 않음) 일부 행을 읽을 수 없으면, 읽은 행까지만 점검하고 실행 보고 첫 줄에 `입력 오류: N행부터 읽을 수 없음`이라고 쓴다. 읽지 못한 행은 결함 없는 행으로 세지 않는다
- 날짜 모양이 틀린 칸(D4)으로는 D1 · D5를 판정하지 않는다
- 링크를 실제로 열어 보지 않는다. 모양만 본다
- 행을 지우라고 하지 않는다. 마감 지난 공고는 화면에서 자동으로 빠진다. 삭제는 운영진이 한다

### 3-1. 금지

- 입력에 없는 키 · 값을 출력에 쓰지 않는다. 근거 칸은 그 행의 값을 그대로 옮긴다
- 결함 기준 밖의 의견(제목이 길다, 공고가 별로다 등)을 붙이지 않는다

## 4. 입출력 계약

### 4-0. 설정 (지시문 맨 위에 둔다)

```
[설정]
기준일: 실행할 때 사용자가 주는 날짜
```

### 4-1. 입력

사용자가 기준일과 공고 탭 데이터(JSON 배열)를 붙여 넣는다. 행마다 칸은 9개다.

```json
[
  {
    "키": "linkareer-354228",
    "제목": "행정안전부 2026 모바일신분증 아이디어 공모전",
    "종류": "공모전",
    "분류": "정부공공",
    "주최": "행정안전부",
    "출처": "링커리어",
    "url": "https://linkareer.com/activity/354228",
    "접수시작": "2026-10-01",
    "접수마감": "2026-10-30"
  }
]
```

**값 목록**

| 종류 | 분류 |
|---|---|
| 공모전 | 정부공공 · 기업 · 학회대학 · 기타 |
| 채용 | 대기업 · 중견중소 · 공기업공공 · 스타트업 · 기타 |
| 자격증 | ADsP · SQLD · 컴활 · SAP · 정보처리기사 · 빅데이터분석기사 · 어학 · 기타 |
| 교내활동 | 비교과 · 특강 · 튜터·멘토 · 장학 · 기타 |
| 대외활동 | 기타 |

### 4-2. 출력

**① 결함표** (결함마다 한 줄)

| 행 | 키 | 결함 | 확신 | 근거(그 행의 값 그대로) | 조치 |
|---|---|---|---|---|---|

- 행 = 입력 배열에서 몇 번째 행인지(1부터)
- 결함 = D1 ~ D9 코드
- 확신 = 3절 표의 값(`확실` · `의심`)

**② 실행 보고**

```
기준일: YYYY-MM-DD
본 행: N
읽은 행: N
결함: N건(확실 N · 의심 N) / D1 N · D2 N · D3 N · D4 N · D5 N · D6 N · D7 N · D8 N · D9 N
결함 없는 행: N
```

결함이 0건이면 첫 줄에 `결함 0건`, 입력 오류가 있으면 첫 줄에 `입력 오류: N행부터 읽을 수 없음`이라고 쓴다.

## 5. 제출 형식

- 에이전트 1개 = 텍스트 파일 1개(.md 또는 .txt), 4,000자 이내
- 새 대화창에 그대로 붙여 넣고 데이터를 넣으면 바로 실행되어야 한다. 특정 서비스의 기능(메모리, 업로드한 지식 파일 등)에 기대지 않는다
- 맨 위에 4-0 설정 블록. 처음 쓰는 사람이 무엇을 붙여 넣으면 되는지 지시문 안에 적혀 있어야 한다
- 워크스페이스 과제 탭에 낸다

## 6. 합격 기준

운영진이 비공개 테스트 세트(실제 공고 탭 데이터에 결함을 섞은 20행 안팎)로 검수한다. 실행 = Claude Code 새 세션 3회 + 다른 회사 AI 새 대화 1회.

채점 단위 = (행, 결함 코드) 한 쌍이다.

| 항목 | 합격선 | 등급 |
|---|---|---|
| 지어내기 | 0건(입력에 없는 키 · 값 언급) | 치명 |
| 잘린 입력 | 입력 오류를 보고함 · 읽지 못한 행을 결함 없는 행으로 세지 않음 | 치명 |
| 형식 | 4-2와 일치(결함 코드 · 행 번호 · 확신 · 실행 보고) | 중대 |
| 검출률 | 3회 평균 90% 이상 | 중대 |
| 판단 결함(D8 · D9) 검출률 | 3회 평균 80% 이상 | 중대 |
| 확신 표기 | D1 ~ D7 · D9를 「의심」으로, D8을 「확실」로 쓴 경우 1회 2건 이하 | 중대 |
| 오탐(결함이 아닌데 결함으로 잡음) | 실행마다 1쌍 이하 | 중대 |
| 일관성 | 3회 모두 찾은 결함이 90% 이상 | 중대 |
| 다른 모델 | 치명 0건 · 검출률 80% 이상 | 중대 |

결과는 셋 중 하나다. 치명 결함이 하나라도 있으면 불합격, 치명은 없고 중대 결함만 있으면 조건부(다시 제출할 때 고치면 합격), 둘 다 없으면 합격. 11/6 1차 결과를 보고 11/9에 한 번 다시 낼 수 있고, 최종 판정은 다시 낸 파일로 한다.

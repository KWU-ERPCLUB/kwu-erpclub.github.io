# 발주서 B · 분야 AI 브리핑 에이전트

AIM 허브 인사이트에 매주 올릴 「분야 AI 브리핑」을 쓰는 에이전트를 발주한다. 받는 것은 완성된 에이전트 하나다. 만드는 방법은 자유다.

## 1. 배경

허브 인사이트는 9/12 이후 새 글이 없다. 자동으로 쓰던 주간 트렌드가 멈췄다. 그 글도 전체 AI 소식이라 금융 · 마케팅처럼 분야를 정한 독자에게는 넓다.

이 에이전트는 사람이 모아 온 기사 메모를 받아 정해진 분야의 AI 소식을 카드 형식 브리핑으로 쓴다. 재료를 찾는 일은 사람이 한다. 고르고 쓰는 일은 에이전트가 한다. 합격 기준을 통과하면 운영진이 매주 자동 실행에 넣는다.

## 2. 발주처 요청문

> 인사이트 편집 담당입니다. 매주 분야별 AI 브리핑을 맡기려고 합니다.
>
> **고르기**
> 1. 설정에 적은 분야와 AI를 함께 다룬 소식만 써 주세요. 둘 중 하나만 다룬 소식은 빼 주세요.
> 2. 매체 · 날짜 · 링크가 다 있는 재료만 써 주세요. 하나라도 없으면 빼 주세요.
> 3. 기준일부터 최근 3주(21일) 안에 나온 기사만 써 주세요.
> 4. 같은 소식을 여러 곳에서 다뤘으면 제일 먼저 나온 기사 하나만 써 주세요.
> 5. 쓸 만한 재료가 3건보다 많으면 최신 3건만 써 주세요. 적으면 있는 만큼만, 없으면 쓰지 말고 알려 주세요.
>
> **쓰기**
> 6. 재료에 없는 사실 · 숫자 · 사람 · 기관은 쓰지 마세요. 숫자는 재료에 적힌 그대로 써 주세요. 반올림하거나 바꾸지 마세요.
> 7. 한 문장은 50자 안으로 써 주세요. 줄표(문장 중간의 긴 가로선)는 쓰지 마세요. 독자에게 「~해야 한다」처럼 권하는 말로 끝내지 마세요. 영어 약어는 처음 나올 때 풀어 주세요.
> 8. 재료가 잘리거나 깨져서 들어오면 쓰지 말고 알려 주세요.

요청문만으로 정해지지 않는 부분은 운영진에게 묻는다. ~10/30까지 받은 질문과 답은 11/1에 모두 공개한다.

## 3. 입력

사용자가 기준일과 재료 메모 여러 건을 붙여 넣는다.

```
기준일: 2026-10-24

## 재료 1
- 제목: ...
- 매체: ...
- 날짜: YYYY-MM-DD HH:MM
- 링크: https://...
- 메모: (기사에서 옮겨 적은 사실 3~5문장)
```

설정은 에이전트 맨 위에 둔다.

```
[설정]
분야: (예: 금융)
독자: AI를 매일 쓰지만 개발은 하지 않는 경영학부 학생
```

## 4. 출력 형식

**① 재료 판정표** (재료 전부)

| 번호 | 제목 | 판정 | 요청 번호 | 근거(재료에서 옮긴 말) |
|---|---|---|---|---|

- 판정 = `사용` · `제외` · `입력 오류`
- 요청 번호 = 제외일 때 1~5 중 하나

**② 브리핑** (사용 재료로)

```markdown
# (분야) AI 브리핑 · (기준일)

요약
- (카드 1의 한 줄 요약, 40자 이내)
- (카드 2의 한 줄 요약, 40자 이내)
- (카드 3의 한 줄 요약, 40자 이내)

## (카드 1 키워드, 8자 이내)
(2~3문장. 무슨 일인지 → 숫자나 사실 하나 → 독자 분야에 어떤 의미인지)
출처: (매체), (날짜), (링크)

## (카드 2 키워드)
...
```

카드는 사용 재료 수만큼(최대 3장) 쓴다. 요약 줄 수는 카드 수와 같다.

**③ 실행 보고**

```
기준일: YYYY-MM-DD
본 재료: N건 / 사용 N · 제외 N · 입력 오류 N
제외 요청별: 1번 N · 2번 N · 3번 N · 4번 N · 5번 N
작성 규칙 자체 점검: 50자 넘는 문장 N · 줄표 N · 권유 종결 N
```

사용 재료가 0건이면 첫 줄에 `브리핑 0건`, 입력 오류가 있으면 첫 줄에 `입력 오류 N건`이라고 쓴다.

## 5. 제출 형식

- 에이전트 1개 = 텍스트 파일 1개(.md 또는 .txt), 4,000자 이내
- 새 대화창에 그대로 붙여 넣고 재료를 넣으면 바로 실행되어야 한다. 특정 서비스의 기능(메모리, 업로드한 지식 파일 등)에 기대지 않는다
- 맨 위에 3절 설정 블록. 처음 쓰는 사람이 무엇을 붙여 넣으면 되는지 지시문 안에 적혀 있어야 한다
- 워크스페이스 과제 탭에 낸다

## 6. 합격 기준

운영진이 비공개 재료 묶음으로 검수한다. 실행 = Claude Code 새 세션 3회 + 다른 회사 AI 새 대화 1회. 검수 설정 = 분야 「경영정보시스템(MIS) · ERP · 디지털전환(DX)」.

| 항목 | 합격선 | 등급 |
|---|---|---|
| 지어내기 | 0건(재료에 없는 사실 · 숫자 · 기관, 숫자 바꿔 쓰기, 다른 재료의 숫자 섞기 포함) | 치명 |
| 출처 없는 재료 · 기간 밖 재료 | 전부 제외 | 치명 |
| 깨진 재료 | 전부 `입력 오류` | 치명 |
| 브리핑 형식 | 4절 ②와 일치(카드 수 · 출처 줄) | 치명 |
| 판정표 · 실행 보고 형식 | 4절 ① · ③과 일치 | 중대 |
| 판정 정확도 | 3회 평균 90% 이상(판정과 요청 번호가 모두 맞아야 1건) | 중대 |
| 일관성 | 3회 모두 같은 판정인 재료 90% 이상 | 중대 |
| 작성 규칙 | 실행마다 위반 1건 이하 | 중대 |
| 다른 회사 AI | 치명 0건 · 정확도 80% 이상 | 중대 |

브리핑 문장의 표현은 실행마다 달라도 된다. 판정과 숫자는 같아야 한다. 결과는 셋 중 하나다. 치명 결함이 하나라도 있으면 불합격, 치명은 없고 중대 결함만 있으면 조건부(다시 제출할 때 고치면 합격), 둘 다 없으면 합격. 11/6 1차 결과를 보고 11/9에 한 번 다시 낼 수 있고, 최종 판정은 다시 낸 파일로 한다.

## 7. 입력 예시와 기대 결과

입력 예시 = `발주서-B-입력예시.md`(재료 8건, 분야 = 금융).

| 재료 | 기대 결과 | 이유 |
|---|---|---|
| 1 | 사용 | 금융(은행 계좌) + AI 에이전트 · 7일 전 |
| 2 | 사용 | 금융보안원 기준 · 같은 소식 중 가장 먼저 나온 기사(10-07 11:30) |
| 3 | 제외 · 4번 | 재료 2와 같은 소식, 더 늦게 나옴(14:04) |
| 4 | 사용 | 보험사 + AI 에이전트 · 2일 전 |
| 5 | 제외 · 1번 | 중심 내용은 소비자용 AI 서비스의 이용자 수 |
| 6 | 제외 · 3번 | 2026-09-07, 기준일로부터 47일 전 |
| 7 | 제외 · 2번 | 링크가 없음 |
| 8 | 입력 오류 | 제목 · 매체 · 메모가 깨짐 |

카드 3장의 숫자는 재료에 적힌 그대로여야 한다(재료 1 = 27개 이상 · 60만 건, 재료 2 = 6개 분야 17개 항목 · 2027년, 재료 4 = 11월).

## 8. 일정

발주서 A 8절과 같다. 10/26 발주 → ~10/30 질문 → 11/1 질문과 답 공개 → 11/2 제출 → ~11/6 검수 결과 → 11/9 다시 제출(1회) → 11/16 자동 실행 등록.

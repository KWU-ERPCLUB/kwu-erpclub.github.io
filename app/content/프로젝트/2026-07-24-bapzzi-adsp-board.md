- ADsP(데이터분석 준전문가) 제50회(2026-08-08) 합격이 목표인 비전공 그룹 스터디. 주 1회 오프라인 + 예습 기반, A·B 2팀.
- 운영 도구 = 직접 만든 진도·성취도 보드(React + Supabase, Vercel 배포). 필요한 도구를 AI 협업으로 만들어 운영에 바로 투입 — 이 기록의 축은 제작 과정이 아니라 **스터디가 도구를 어떻게 활용했고, 도구가 운영을 어떻게 바꿨는가**. 화면 속 이름은 블러 또는 게스트 계정 처리.

### 06-26 · 스터디 시작 — 운영 모델 확정

- **모델** = 주 1회 오프라인 + 예습 기반. 각자 예습 → 모임은 개념 질의·빈출 정리, 마무리 회차는 모의고사·오답.
- **범위** = 과목 순차(1→2→3) + 막판 기출·모의고사. 진도 관리 방식은 이 시점엔 미정.

### 06-28 · 진도 보드 제작 — 수기 집계를 웹앱으로

- **문제** = 진도 체크·성취도 집계를 매주 사람 손으로 걷어야 함.

::: 결정
진도 집계를 수기로 할 것인가 | 웹앱 제작 — 당일 MVP 배포 | 매주 걷는 수고 제거, 학습 기록이 자동으로 쌓임 | 수기 집계 유지
:::

- 팀원=진도 체크·퀴즈 응시 / 운영자=일정·문항·공지 관리, 권한 분리. 가입 없이 이름+PIN 입장 — 8명에게 가입 절차를 요구하면 그 자체가 이탈 지점.
- **AI 활용** = 자가검증 루프(변경 → 자동 캡처 → 자가비판 → 개선)로 완성도를 끌어올림. 하루 만에 숫자 나열 현황이 비교·추이 시각화로 발전.

### 07-01~02 · ⭐콘텐츠 원천 재구축 — 만든 걸 버린 결정

- **발단** = 초기 자료의 원천이 유튜브 요약 강의 — 학습하며 정리한 내용과 어긋나는 지점이 발견됨.

::: 분기점
문제 | 강의 기반 자료가 어긋남 — 출처를 되짚을 수 없는 자료는 틀렸을 때 고칠 수 없음
따진 대안 | 어긋난 부분만 부분 수정하며 기존 자료 유지
결정 | 전량 폐기 — 직접 학습·정리한 내용을 유일 원천으로 재구축, 모든 문항에 출처 표기
버린 것 | 이미 만든 1·2과목 정리본·문제은행 전부
결과 | 이후 모든 콘텐츠(919문항)가 출처를 되짚어 수정 가능한 구조
:::

- 학습 단위도 임의 배분(20일차)에서 과목 체계 그대로의 **절 29개**로 재정의. 어느 절을 아는지/모르는지가 드러나는 단위.
- **AI 활용** = 정리한 내용을 절 단위 문항·정리본으로 가공. 병렬 분업으로 단기간에 전 범위 제작 — 이후 증보를 거쳐 총 919문항.

### 07-02~03 · 지표 체계 정립 — 하나의 '성취도'를 넷으로

- **문제** = 정답률·진행도가 계산마다 다르게 읽힘(팀 피드백: 지표 혼선). 하나의 숫자로 뭉치면 진도를 안 나간 사람과 정확도가 낮은 사람이 같은 숫자로 보임.

::: 결정
지표를 하나로 합칠 것인가 | 4지표 분리 — 정답률·진행도·실전점수·종합준비도, 혼용 금지 | 무엇을 해야 하는지가 다르면 지표도 달라야 함 | 단일 '성취도' 점수
:::

::: 비교
/img/projects/adsp/shot-metrics-before.png | 정립 전 — 점수·진도·기출이 한 화면에 뒤섞임(14점·1/29·63점)
/img/projects/adsp/shot-metrics-after.png | 정립 후 — 종합준비도·진행도·정답률·실전점수 4카드 분리
:::

- 절 완료 조건 = 정리본 학습 체크 **AND** 진행도 100%. 정리본만 넘겨보고 완료 처리하는 걸 막음.

### 07-05 · 운영을 데이터로 검증 — 감독 리포트

- 주간 스냅샷 → 6섹션 고정 템플릿 리포트(참여 지속성·사용성 공백·지난주 결정의 결과·표적 질문).
- 1회차 기준선에서 발견: 자료와 도구는 갖췄는데 쓰는 사람이 적음 → 첫 과제를 콘텐츠 추가가 아니라 **온보딩**으로 전환. 사용법 가이드·접속 로그·공지 읽음 추적이 여기서 나옴.
- 역할 경계: 분석·제안은 도구가, **결정과 소통은 사람이**.

### 07-07 · 진행도 재정의 — 정확한 지표가 쓸모없을 수 있다

- **발단** = "2일차인데 진행도가 17%?"라는 신고.
- **확인** = 산술은 맞았음(54/316 = 17.1%). 버그가 아니라 **지표 정의가 체감과 어긋난 것**.

::: 결정
지표를 고칠 것인가 화면을 고칠 것인가 | 진행도를 완료 일차/25로 전면 교체 | 학습자는 "오늘 몫을 했나"로 위치를 잼 — 문항 비율은 정확해도 행동으로 옮길 수 없음 | 문항 커버리지 유지 + 설명 추가
:::

### 07-16~24 · 이탈 방지·운영 조정

- **주차 점검 퀴즈**(점검일에 그 주 핵심 문항) — 수동 체크는 자기 신고라 검증이 안 됐음. **연속 학습 배지** — 절 체크·퀴즈·점검 중 하나만 해도 그날 인정.
- **07-24 중간 점검** = 보드 랭킹·학습현황 데이터로 팀별 진도차 확인 → 속성 세션(1·2과목 마감 + 3과목 기출 병행).

### 07-26 · 실전 조건 재현 — 시험 그대로

- 실사용 피드백("실제 문제와 다르게 보인다")을 받아 문항 표시를 시험 지면 형태로 개편 — 계산·그림 유형 보강, 개념 도해 SVG 추가.
- **실전 조건 재현**: 전과목 실전에 90분 카운트다운(만료 시 입력 잠금·자동 채점) + 응시 전 안내. 실제 시험이 50문항 90분이므로.

### 앞으로의 활용

- **후속 기수·다른 스터디로 이식** — 절(단원) 체계·퀴즈·실전 모드·지표 4종은 특정 시험에 묶여 있지 않음. 콘텐츠만 갈아끼우면 다른 자격증 스터디에서 같은 틀로 운영 가능.
- **방법 자체가 자산** — 필요한 운영 도구를 AI 협업으로 직접 만들어 완성도를 끌어올리는 접근. 이번 운영에서 반복 확인한 루프(필요 발견 → 제작 → 실사용 피드백 → 개선)는 도구가 달라져도 재사용됨.

### 운영 지표 (스터디 진행 중)

- 참여·활용 지표는 **스터디 진행 중 — 제50회(8/8) 이후 공개.**
- 공개 예정 틀: 온보딩 전→후 활성 인원 변화 / 주차 점검 퀴즈 응시율 / 연속 학습 배지 분포.

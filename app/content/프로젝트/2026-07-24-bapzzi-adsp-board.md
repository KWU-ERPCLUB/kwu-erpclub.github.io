### 06-26 · 스터디 시작 — 운영 모델 확정

- **모델** = 주 1회 오프라인 + 예습 기반. 각자 정리자료로 예습 → 모임은 개념 질의·빈출 정리, 마무리 회차는 모의고사·오답.
- **범위** = 과목 순차(1→2→3) + 막판 기출·모의고사. 진도 관리 방식은 이 시점엔 미정.

### 06-28 · 진도 보드 제작 — 수기 집계를 웹앱으로

- **문제** = 진도 체크·성취도 집계를 매주 사람 손으로 걷어야 함.
- **결정** = 웹앱 제작, 당일 MVP 배포(React + TypeScript + Supabase + Vercel). 팀원=진도 체크·퀴즈 응시 / 운영자=일정·문항·공지 관리, 권한은 Postgres RLS로 분리.

### 06-29 · 하루 4개 버전 — MVP를 실사용 앱으로

- **문제** = 기능은 도는데 비교·추이가 안 보임(숫자 나열).
- **결정** = 랭킹 막대·종합준비도 도넛·기출 추이 그래프를 차트 라이브러리 없이 SVG로 직접 구현. 기출 점수는 '회차 공유 모델'(운영자가 회차 등록 → 전원 같은 기준 입력, RLS + RPC).
- **AI** = 자가검증 루프(변경 → Playwright 자동 캡처 → 자가비판 → 개선). 이 문서의 버전별 화면이 그 산출물. 67테스트 유지.

### 07-01~02 · 교재 단일원천 전환 — 콘텐츠 전면 재제작

- **문제** = 초기 자료의 원천이 유튜브 요약 강의 — 정확성 검증 불가.
- **결정** = 전부 폐기, 교재 스캔 555장을 AI가 직접 판독해 절 단위 정리본·퀴즈로 재제작. 모든 문항에 교재 페이지 역참조.
- **AI** = 병렬 서브에이전트로 분업 제작 → 전수 검증. 하루 만에 교재 전 범위 신규 603문항.

### 07-02~03 · v2.0.0 — 지표 체계 정립·전과목 실전

- **문제** = 정답률·진행도가 계산마다 다르게 읽힘(팀 피드백: 지표 혼선).
- **결정** = 지표 사전 정립(정답률=누적 · 진행도 · 실전점수 · 종합준비도) 후 화면을 지표에 맞춰 재설계. 전과목 실전(모의 3회·기출 3회) 전체화면 시험 + 채점 리뷰. 온보딩은 실화면 캡처 가이드.

### 07-05~07 · 운영 중 개편 — 지표를 학습 일정 기준으로

- **문제** = 계획대로 해도 2일차 진행도가 17% — 지표가 학습 일정과 어긋남.
- **결정** = 진행도를 "완료 일차 ÷ 25"로 재정의. 정리본을 끝까지 읽어야 완료 체크가 열리고 바로 퀴즈로 이어지는 동선. 게스트 계정은 랭킹·통계 제외.
- **AI** = 원인을 산술로 확정(54/316 = 17.1%)한 뒤 재설계.

![개편 후 홈 — 오늘 할 진도·밀린 범위·랭킹·캘린더](/img/projects/adsp/home-now.png)

### 07-24~26 · 실전 대비 마감 — 시험 조건 재현

- **중간 점검** = 보드 랭킹·학습현황 데이터로 팀별 진도 차이 확인 → 속성 세션(1·2과목 마감 + 3과목 기출 병행).
- **결정** = 문항을 시험 지면 그대로(R 콘솔 출력·거래표 고정폭 렌더, 개념 도해 SVG 8장, 계산·그림 신규 42문항 전수 검산) + 전과목 실전에 90분 카운트다운(만료 시 자동 채점).
- **AI** = 설계·검증은 상위 모델, 구현은 하위 모델 서브에이전트 7개로 분업. 랭킹 진도 저평가 버그는 라이브 데이터 조회로 근본원인(API 1,000행 절단) 확정 후 수정. 183테스트.

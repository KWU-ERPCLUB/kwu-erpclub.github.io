- ADsP(데이터분석 준전문가) 제50회(2026-08-08) 합격이 목표인 비전공 그룹 스터디. 주 1회 오프라인 + 예습 기반, A·B 2팀 운영.
- 운영 도구 = 직접 만든 진도·성취도 보드(React + Supabase, Vercel 배포) — 교재 전 범위 정리본·퀴즈·모의고사를 보드에서 학습.
- 아래 = 스터디 시작 → 보드 탄생 → 운영·개선의 여정. 단계마다 AI(Claude Code) 활용 방식 병기. 화면 속 이름은 블러 처리.

### 2026-06-26 · 스터디 시작 — 운영 모델 확정

- 주 1회 오프라인 + 예습 기반: 각자 정리자료로 예습 → 모임 = 개념 질의·빈출 정리, 마무리 회차 = 모의고사·오답.
- 범위 = 과목 순차(1→2→3) + 막판 기출·모의고사. 진도 관리 방식은 이 시점엔 미정 — 정리자료 배포만 계획.

### 2026-06-28 · 보드 탄생 — 진도 관리를 웹앱으로

- 진도 체크·성취도 집계를 수기로 모으는 대신 웹앱 제작으로 결정. MVP를 만들어 당일 배포(React + TypeScript + Supabase + Vercel).
- 역할 분리 = 팀원: 진도 체크·퀴즈 응시 / 운영자: 일정·문항·공지 관리. 권한은 Postgres RLS로 분리.

![초기 보드 메인 — 스터디원 현황·캘린더](/img/projects/adsp/v1-0-dashboard.png)

### 2026-06-29 · 하루 4개 버전 — MVP를 실사용 앱으로 (v1.0.0→v1.3.0)

- 메인 = 스터디원 비교 막대, 내정보 = 종합준비도 도넛, 기출 추이 그래프 — 차트 라이브러리 없이 SVG 직접 구현(번들 ~140kB gzip 유지).
- 기출 점수 '회차 공유 모델': 운영자가 회차를 등록하면 전원이 같은 기준으로 입력(RLS + RPC 권한 분리).
- AI 활용 = 자가검증 루프(변경 → Playwright 자동 캡처 → 자가비판 → 개선). 이 문서의 버전별 화면도 그 산출물. 67테스트 유지.

### 2026-07-01 · 콘텐츠 전면 개편 — 교재 단일원천

- 유튜브 요약강의 기반 초기 자료 전부 폐기 → 교재 스캔 555장을 AI가 직접 판독해 절 단위 정리본·퀴즈로 재제작.
- 규칙 = 모든 문항·정리에 교재 페이지 역참조, 억지 암기법 금지.
- 다음 날(07-02) 교재 전 범위 콘텐츠화 완료 — 신규 603문항(병렬 서브에이전트 제작 → 전수 검증).

### 2026-07-02~03 · v2.0.0 — 지표 체계 정립·전과목 실전

- 지표 사전 정립: 정답률(누적) · 진행도 · 실전점수 · 종합준비도 — 팀 피드백(지표 혼선)을 정의 확정으로 수렴.
- 전과목 실전(모의고사 3회·기출 3회): 전체화면 시험 + 채점 리뷰(틀린 범위·오답 목록).
- 온보딩 = 실화면 캡처에 라벨을 얹은 사용법 가이드 페이지. 팀 표시명 A·B팀 전환.

### 2026-07-05~07 · 운영하며 고치기 — 지표를 사람 기준으로

- 진행도를 문항 커버리지에서 "완료 일차 ÷ 25"로 전환 — 계획대로 해도 2일차에 17%가 떠 일수 직관과 어긋났기 때문. 스터디원 멘탈모델(n일차/25일)에 지표를 맞춤.
- 정리본을 끝까지 읽어야 완료 체크가 열리고, 체크 옆에서 바로 퀴즈로 이어지는 동선. 비스터디원 게스트 계정은 랭킹·통계에서 제외.
- AI 활용 = 근본원인 산술 검증(54/316 = 17.1%)으로 "왜 17%인가"를 확정한 뒤 지표 재설계.

### 2026-07-24 · 중간 점검 — 팀별 진도 차이 대응

- 보드 랭킹·학습현황 데이터로 팀별 진도 차이 확인 → 속성 세션 운영(1·2과목 마감 + 3과목 기출 병행).

### 2026-07-26 · 실전 대비 마감 — 문항 가독성·90분 타이머

- 문항 렌더러 개편: R 콘솔 출력·거래표를 시험 지면처럼 고정폭·정렬 보존으로 렌더, 개념 도해 SVG 8장, 계산·그림 신규 42문항(전수 검산).
- 전과목 실전에 90분 카운트다운 — 실제 시험 조건(50문항 90분) 재현, 만료 시 자동 채점.
- 주차 점검 퀴즈·연속학습 배지·진도 자동 갱신. 랭킹 진도 저평가 버그는 라이브 데이터 조회로 근본원인(API 1,000행 절단)을 확정하고 수정.
- AI 활용 = 설계·검수와 구현을 모델 등급으로 분업(서브에이전트 7개 병렬), 교재 스캔 수치 대조 스팟체크. 183테스트.

# 공고 수집 하네스 (2026-08-19 신설)

자동 루틴이 매번 같은 기준으로 돌도록 **수집 대상·필터·판정**을 고정한 문서.
사람이 수동으로 채울 때도 같은 기준을 쓴다.

- 원천 파일 = `site/supabase/postings.json` (여기를 갱신 → push → CI가 DB upsert)
- 분류 값의 유일 원천 = `app/src/workspace/postings-taxonomy.js` (목록 밖 값 = 검증 실패)
- 검증 = `node scripts/sync-postings-db.mjs --dry` (네트워크 0)

---

## 0. 독자 정의 (모든 판정의 분모)

광운대 경영학부 재학생, AI·데이터에 관심 있으나 **비개발자**.
2~4학년, 학기 중 주 1회 스터디 참여. 취업 준비 국면.

이 사람이 **클릭할 이유가 없으면 넣지 않는다.** 링크 수를 늘리는 것은 목적이 아니다.

## 2. 교내 루틴 — 수집 절차

**대상 URL(고정)**

```
https://www.kw.ac.kr/ko/life/notice.jsp?BoardMode=list&searchKey=1&searchVal=&srCategoryId=&tpage=1
```

1. 목록을 읽어 **등록일이 최근 7일 이내**인 항목만 후보로 둔다.
2. 후보 중 §4 채택 기준을 통과한 것만 상세(`BoardMode=view&DUID=...`)를 연다.
3. 상세 본문에 마감일이 없고 첨부(hwpx·pdf)뿐이면 → **웹 검색으로 원 공고를 한 번 더 찾는다.**
   원 공고를 찾으면 그 URL과 날짜를 쓴다. 못 찾으면 날짜 `null` + 공지 URL로 등재하되,
   코멘트 끝에 세부 일정 확인이 필요하다는 사실을 적는다.
4. 이미 `postings.json`에 있는 키는 **날짜·코멘트만 갱신**한다(제목·키 변경 금지).

**교내 분류 배정**

| 공지 성격 | 종류 | 분류 |
|---|---|---|
| 교내·외부 공모전, 경진대회, 해커톤 | 공모전 | 학회대학(교내 주최) / 정부공공·기업(외부 주최) |
| 비교과 프로그램, 특강, 튜터·멘토 모집, 교내 장학, 교내 캠프 | 대외활동 | 교내프로그램 |
| 교내 기관 직원·조교 채용 | 채용 | 기타 |

## 3. 외부 루틴 — 수집 절차

**대상 URL(고정)**

| 소스 | URL | 뽑는 것 |
|---|---|---|
| 링커리어 공모전 | `https://linkareer.com/list/contest` | 데이터·AI·기획·경영 분야 |
| 링커리어 대외활동 | `https://linkareer.com/list/activity` | 데이터·AI·IT·기획 분야 |
| 사람인 하반기 공채 | `https://m.saramin.co.kr/live-job/view?idx=109953` | 대기업 신입·인턴 일정표 |
| 잡코리아 공채 달력 | `https://www.jobkorea.co.kr/starter/calendar` | 위 표의 교차 검증 |

1. 목록에서 후보를 뽑되 **D-day를 그대로 믿지 않는다.** 채택 후보는 개별 상세 페이지를 열어
   `YYYY-MM-DD` 접수 시작·마감을 확인한 뒤 기록한다.
2. 채용은 **공식 채용 사이트 URL**을 쓴다. 검증되지 않은 도메인은 추측해서 넣지 않는다
   (확인 못 하면 그 항목을 건너뛴다 — 죽은 링크가 목록 신뢰를 깎는다).
3. 마감이 **3일 이내**인 신규 항목은 넣지 않는다. 다음 루틴 실행 전에 마감돼 목록만 어지럽힌다.

## 4. 채택 기준 (전부 T여야 등재)

- [ ] **T1 접근 가능** — 광운대 학부생이 지원 자격을 충족한다(대학원생 전용·특정 학과 전용·재직자 전용 = 탈락)
- [ ] **T2 비용 0원** — 참가비·수강료가 없다(학생 부담 0원 정책)
- [ ] **T3 비개발자 진입 여지** — 기획·문서·분석 축으로 참여할 구간이 있다.
      모델 구현·코딩 실력만으로 승부가 갈리는 대회는 탈락
- [ ] **T4 날짜 확인** — 접수 마감 또는 시험일을 원문에서 확인했다(못 찾으면 `null` + 코멘트에 명시)
- [ ] **T5 한 줄 이유** — "우리에게 왜 유효한가"를 한 문장으로 쓸 수 있다

T3의 예외 = **채용**. 채용은 T3 대신 **경영·DX·IT서비스·구매/SCM 직군이 열려 있는가**로 판정한다.

## 5. 코멘트 작성 규칙

카드에서 제목 다음으로 읽히는 한 줄. 여기가 이 보드와 링크 모음의 차이다.

- 공고를 **요약하지 않는다.** 요약은 원문 링크가 한다
- 쓰는 것 = 이 공고의 **판단 재료** 하나. 접수창 길이, 팀 구성 제약, 병행 가능 여부,
  다른 일정과의 충돌, 우리 학습 축과 닿는 지점 중 하나를 고른다
- 금지 = 과장·권유("꼭 지원해 보세요"), 마케팅 어투, 내부 구현 용어
- 길이 = 한 문장 또는 두 문장. 카드가 2줄로 잘린다

## 6. 고정(★) 기준

`고정: true` = 운영진 추천 섹션에 올라간다. **동시에 5건을 넘기지 않는다.**
기준 = ①AIM 학습 축과 직접 닿음 ②접수창이 짧아 놓치기 쉬움 — 둘 중 하나.

## 7. 내리기

이 파일에서는 삭제하지 않는다(동기화는 upsert만 한다).
마감된 공고는 화면에서 자동으로 빠진다. 완전히 내릴 때만 운영 탭에서 사람이 삭제한다.

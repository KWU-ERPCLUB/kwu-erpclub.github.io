# 공고 수집 하네스 (2026-08-19 신설 → 같은 날 2차 개정)

자동 루틴이 매번 같은 기준으로 돌도록 **수집처·채택 기준·제외 목록**을 고정한 문서.
사람이 수동으로 채울 때도 같은 기준을 쓴다.

- 원천 파일 = `site/supabase/postings.json` (여기를 갱신 → push → CI가 DB upsert)
- 분류 값의 유일 원천 = `app/src/workspace/postings-taxonomy.js` (목록 밖 값 = 검증 실패)
- 검증 = `node scripts/sync-postings-db.mjs --dry` (네트워크 0)

---

## 0. 이 보드가 하는 일

**여러 사이트에 흩어진 공고 링크를 한 곳에 모아 바로 연결해 주는 것.**
스터디원이 링커리어·잡코리아·사람인을 각각 들어가 보지 않아도 되게 하는 편의 기능이다.

따라서 화면에 남는 것은 **제목·출처·마감일**뿐이다.
- 코멘트("왜 유효한가")는 더 이상 필수가 아니다 — 쓰지 않아도 된다
- 공고 내용을 요약하지 않는다. 그건 원문이 한다
- 우리가 하는 유일한 판단 = **"이걸 목록에 넣을 것인가"** 하나뿐

## 0-1. 독자

광운대 경영학부 재학생, AI·데이터에 관심 있으나 **비개발자**. 2~4학년, 취업 준비 국면.

**공모전 ②의 판정법**: "이 제출물을 AI에게 시켜서 만들 수 있는가"를 묻는다.

## 2-1. 공통 조건 (종류 무관, 전부 T여야 등재)

- [ ] **T1** 광운대 학부생이 지원할 수 있다 (대학원생 전용·특정 학과 전용·재직자 전용 = 탈락)
- [ ] **T2** 참가비·수강료가 없다 (학생 부담 0원)
- [ ] **T3** 원문 링크가 살아 있다 (`javascript:void`·로그인 벽 = 탈락)
- [ ] **T4** 마감일을 확인했다 — **예외 = 광운대 교내 공지**(§3-3)
- [ ] **T5** 이미 마감되지 않았다. 마감이 **3일 이내**인 신규 항목도 넣지 않는다(다음 실행 전에 죽는다)

## 3. 교내 루틴 — 광운대

**대상 URL(고정)**

```
https://www.kw.ac.kr/ko/life/notice.jsp?BoardMode=list&searchKey=1&searchVal=&srCategoryId=&tpage=1
```

1. 목록에서 **등록일이 최근 7일 이내**인 항목만 후보로 둔다.
2. §2 표의 '교내' 행 + §2-1로 판정한다. **대부분 탈락하는 게 정상** — 하루 0건이어도 좋은 결과다.
3. 상세(`BoardMode=view&DUID=...`)를 열어 마감일을 찾는다. 본문 없이 첨부(hwpx·pdf)뿐이면
   **웹 검색으로 원 공고를 한 번 더 찾는다.**
4. **날짜를 못 찾아도 등재한다**(오너 2026-08-19) — 날짜 칸을 비우고 올린다.
   교내 정보를 놓치는 것보다 날짜가 빈 채로 링크가 있는 편이 낫다. 추정 날짜를 쓰지는 않는다.

**분류 배정**

| 공지 성격 | 종류 | 분류 |
|---|---|---|
| 교내·외부 공모전, 경진대회, 해커톤 | 공모전 | 학회대학(교내 주최) / 정부공공·기업(외부 주최) |
| 비교과 프로그램, 교내 캠프 | 교내활동 | 비교과 |
| 특강, 명사 초청 강연 | 교내활동 | 특강 |
| 튜터·멘토·또래코치 모집 | 교내활동 | 튜터·멘토 |
| 교내 장학·장학재단 선발 | 교내활동 | 장학 |
| 교내 기관 직원·조교 채용 | 채용 | 기타 |

| 큐넷 | `https://www.q-net.or.kr` | 자격증 회차 확인용 |

1. 목록에서 후보를 뽑되 **D-day를 그대로 믿지 않는다.** 채택 후보는 개별 상세를 열어
   `YYYY-MM-DD` 접수 시작·마감을 확인한다.
2. 채용은 **공식 채용 사이트 URL**을 쓴다. 확인 못 한 도메인은 추측하지 말고 그 항목을 건너뛴다
   (죽은 링크가 목록 신뢰를 깎는다).
3. `출처` 필드에 어느 사이트에서 왔는지 적는다(링커리어·잡코리아·사람인·위비티·광운대).
   화면에 배지로 뜨고 검색에도 걸린다.

## 5. 총량 상한

- 1회 실행당 신규 편입 = **종류별 최대 5건**
- 마감 전 활성 항목이 종류별 **30건 이상**이면 그 종류는 신규 보류

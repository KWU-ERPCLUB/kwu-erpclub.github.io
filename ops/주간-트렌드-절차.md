# 주간 AI 트렌드 발행 절차 (AI 프롬프트 겸 사람 절차) — 2026-09-12 개편판

> 이 문서 = 매주 월요일 「주간 AI 트렌드」 기사의 **운영 원천**. 자동 루틴이 죽어도 이 문서로 재구축·수동 실행이 된다.
> 사용법 ① AI에게: 이 문서 전체를 붙여 넣고 "이 절차대로 이번 주 트렌드 발행"이라고 지시. ② 사람이: §6 사람 폴백.
> 개편 배경(2026-09-11~12 오너, spec = `erp-club/docs/specs/2026-09-11-인사이트-개편.md`): 발행량 과다·공식 발표 쏠림·썸네일 동일·본문 밀도.
> **주간 보고 = 유일한 소재 입구.** 심층은 이 글의 후보 표를 거친 소재만 쓴다(`인사이트-발행-절차.md`).

## §0 독자·초점 (모든 판정의 기준점)

- **주 독자 = AIM 스터디원** — 광운대 경영학부 중심, AI에 관심 있는 비개발자, 취업 준비 국면.
- **관문 ⓪**: AI가 소재의 중심이고, 이 독자가 쓰거나 이해할 접점이 있는가. 채용·ERP·업계 소식이라도 AI가 조연이면 탈락. AI 소식이라도 접점이 없으면 탈락.
- **3축**(항목마다 1개): `AI활용`(AI를 쓰는 방식이 바뀌는 것 — 도구·워크플로·에이전트 운용법·정착 중인 개념) / `AI×취업`(AI 역량이 국내 채용에 어떻게 반영되나) / `AI×MIS`(AI가 기업 정보시스템·업무를 어떻게 바꾸나 — ERP·SI/DX·도입 사례). 정의·경계 = spec §2-2.
- **공식 발표(모델 출시·신기능·제휴)·투자·M&A·실적 = "그 외 한 줄"에만.** TOP·브리핑 카드에 올리지 않는다.

## §1 리서치 창·제목·파일

- 창 = 직전 7일(실행일 미포함 — 월요일 실행이면 지난주 월~일). 제목 = `주간 AI 트렌드 — M월 N주`(제목의 대시는 화면에서 줄바꿈으로 표시되므로 허용).
- 파일 = `../app/content/기사/YYYY-MM-DD-<작성자>-weekly-trend-wNN.md` (wNN = 리서치 창의 ISO 주차).
- 멱등: 같은 wNN 파일이 있거나 최신 weekly 파일이 4일 이내면 스킵.

## §2 리서치

창 안의 AI 소식을 **3축 합쳐 12~18건 + 그 외 ≤5건** 모은다. 각 항목 = 날짜 · 축 · 키워드(8자 이내) · 2~3문장 요약 재료 · 원출처 링크 1 · **증거 링크**(사용 흔적·채택 증거: 커뮤니티 스레드·GitHub·채용 공고·도입 사례. 발표문·보도자료 제외) 0~3 · 국내 함의 링크 0~1.

소스 = `인사이트-발행-절차.md` §3과 동일(A 공식 / B 커뮤니티 / C 발견 채널 / D 데이터). B등급을 A와 동급 비중으로 순회하고, 날짜 검색과 별도로 **담론 갈래**("이번 주 커뮤니티 화두 개념")도 검색해 관측 개념을 `개념-레이더.md`에 등재·갱신한다.
사건 날짜 = 1차 발표일(하네스 F2). 링크는 접속 확인된 것만.

## §3 선별

- **TOP 3** = 3축 안에서만. **AI활용 축 최소 1건 + 국내 최소 1건.** 순위 = 독자가 배우거나 써먹는 변화 > 국내 > 최신.
- **브리핑** = 축별 소절(`### AI활용` / `### AI×취업` / `### AI×MIS`). 항목 = 카드(키워드·축·2~3문장·출처). TOP에 오른 소재는 중복 등재 금지.
- **그 외 한 줄** = 공식 발표·투자·시장·크리에이티브·규제. 한 줄씩 최대 5줄. 이 소절 밖으로 못 나온다.
- **심층 후보 판정**(frontmatter `심층후보`, 독자 비노출): 후보 0~5건에 ⓪~⑤를 T/F로. ⓪ AI 중심·독자 접점 / ① 축 귀속 / ② 국내 함의 링크 ≥1 / ③ 증거 링크 ≥2 / ④ 발표·투자·재무·인사가 중심 아님 / ⑤ 최근 30일 심층과 소재 중복 없음 / **⑥ 심층 6칸(질문 3·실물 해부·앞선 사례 2·판정 기준 발언 1·확인 안 된 것)을 채울 근거가 보이는가**. 전부 T인 것만 심층 후보. 행 서식 = `k | 소재 | 축 | TTTTTTT | 증거 링크 수`(T/F 7자, ⓪~⑥ 순).

## §4 작성 — 서식(순서 고정, 검증기가 검사)

frontmatter: `title` / `author` / `date` / `시각` / `source_url`(TOP 1 원문) / `source_name` / `성격: 트렌드` / **`축`**(= TOP 1의 축) / `시리즈: weekly` / `설명`(1줄) / `태그`(1~5) / **`이미지`**(= TOP 1 소재의 실제 이미지, 1200×750 JPEG, `public/img/covers/`, SOURCES.md 1줄) / **`이미지설명`** / **`심층후보`**(배열 — 콤마 없이 `|` 구분). `주제`는 쓰지 않는다(폐지).

본문:
1. `::: 요약` — 30초 요약 3줄(각 40자 이내) + 「나한테 왜」 1줄
2. `## 이번 주 TOP 3` → `::: 탑` — 행 = `번호 | 축 | 제목 | 본문 2~3문장 | URL | 출처명`
3. `## 이번 주 브리핑` → `### AI활용` / `### AI×취업` / `### AI×MIS` 각각 `::: 브리핑` — 행 = `키워드 | 축 | 본문 2~3문장 | URL | 출처명`. 소재 없는 축은 소절 생략
4. `### 그 외 한 줄` — `- **키워드**: 한 줄 (링크)` 최대 5줄
5. `::: 출처` — 전 링크(`이름 | URL`)

규칙: 분량 ≤ 2,500자(공백·링크·출처 제외 — 검증기) · 항목당 2~3문장, 문장 ≤ 50자 · **대시(—) 금지**(본문; 카드 제목 포함) · 볼드는 항목당 1곳 · 용어는 첫 등장에 괄호 풀이 · 커뮤니티 소재 비단정 화법 · 볼드 뒤 한글 붙여쓰기 금지(`**79%**다` ✗ → `**79%다**` 또는 문장 재배치) · 다른 기사 언급 금지.
카드 렌더 = `app/src/pages/Markdown.jsx` `탑`·`브리핑` 컨테이너(축 라벨 3색·번호 배지·출처 링크).

## §5 검수·게재

1. `기사-검수-하네스.md` §4 전항 T(주간 항목 포함).
2. `cd app` → `npm run validate`(축·이미지·분량·대시·심층후보 서식 검사) · `npm test` · `npm run build` 통과 → main commit·push(콘텐츠 예외).
3. 종료 보고 = 게재 링크 · TOP 3 한 줄씩 · 브리핑 건수(축별) · **심층 후보 표(⓪~⑥ 통과 건수)** · 이미지 출처 · 자검 통과.

## §6 사람 폴백

1. 국내 매체(전자신문·디지털데일리·이데일리·한경)·채용 플랫폼·HN·GitHub·SAP News를 훑어 축별 2~4건씩 고른다.
2. 관문 ⓪과 3축으로 거른다. 발표·투자는 "그 외 한 줄"로.
3. 최근 weekly 파일을 열어 같은 서식으로 쓴다(카드 행 서식 그대로). 심층후보는 자신 없으면 빈 배열.
4. GitHub 웹에서 commit → Actions 초록 확인.

# 주간 AI 트렌드 발행 절차 (AI 프롬프트 겸 사람 절차)

> 이 문서 = 매주 월요일 「주간 AI 트렌드」 기사의 **운영 원천**. 자동 루틴이 죽어도 이 문서로 재구축·수동 실행이 된다.
> 사용법 ① AI에게: 이 문서 전체를 붙여 넣고 "이 절차대로 이번 주 트렌드 발행"이라고 지시.
> 사용법 ② 사람이: §5 사람 폴백을 따른다.
> 원칙 = **얕고 넓게**. 심화 금지(중요 주제는 별도 기사 소재로 제안만). 모든 항목에 링크. 어그리게이터 단독 출처 배제.

## §1 리서치 창·제목

- 창 = 직전 7일(실행일 미포함 — 월요일 실행이면 지난주 월~일)
- 제목 = `주간 AI 트렌드 — M월 N주`
- 파일 = `../app/content/기사/YYYY-MM-DD-<작성자>-weekly-trend-wNN.md` (wNN = **리서치 창이 속한 ISO 주차**, 실행일 주차 아님)

## §2 리서치

창 안의 AI·엔터프라이즈/MIS 뉴스 10~14건 수집. 각 항목 = 날짜·한 줄 요약·링크 1(1차 출처 우선)·주제 enum 1·중요도(TOP급/브리핑급).

다각 스윕 축: OpenAI/Anthropic/Google · 엔터프라이즈·SAP · 규제 · 시장 · 한국 · **크리에이티브·미디어**(영상·이미지 AI 출시, AI 영화제·공모전, AI 영상 외주·광고 시장 — 매주 확인, 있으면 포함).

소스 풀·인용 규칙 = `인사이트-발행-절차.md` §3과 동일(발견 채널과 인용 출처 구분·원출처 인용).

## §3 선별·작성

- TOP 3 = 임팩트 + MIS 관련도(ERP×AI 소재 승격 우대). 창 밖 항목은 본문에 날짜 명시 시에만 허용.
- 출처 필터: 어그리게이터 단독 소스 제외. 공식 발표·주요 매체·복수 확인 건만.
- frontmatter(전체 규격 = `../CONTRIBUTING.md`): `성격: 트렌드`(고정) · `주제: 시장·생태계`(고정) · `시각:`(HH:MM KST) · `설명:`(필수 — "매주 월요일 발행하는 주간 AI 트렌드. M/D–M/D 소식.") · `태그:`(선택 1~5, `#` 없이 배열)
- 본문 형식(순서 고정):
  1. `::: 요약` — 2~3줄
  2. `## 이번 주 TOP 3` — 각 3~4문장, 숫자는 볼드
  3. `::: 용어` — 그 절에 비개발자가 모를 용어가 있을 때만(없으면 생략)
  4. `## 한 줄 브리핑` — 5~7건 권장·최대 8: **날짜** — 한 줄 + 링크
  5. `::: 출처` — 전 링크
- 분량 = 전체 1,500~2,500자. 핀 고정(`고정` 필드) 안 씀.
- 서식 함정(볼드 플랭킹·물결) = `인사이트-발행-절차.md` §5와 동일.
- 금지: 심층처럼 깊게 파기 / 링크 없는 항목 / 지난 기사 언급("지난주 다뤘듯" — 각 기사 독립).

## §4 검수·게재·마감

1. push 전 `기사-검수-하네스.md` §4 전항 T — 특히 사건일=1차 발표일·인용↔본문 수치 일치·마감 지난 정보 배제
2. `cd app` → `npm run validate`·`npm test`·`npm run build` 전부 통과 → **main에 commit·push**(콘텐츠 예외) → Actions 초록 확인
3. TOP 중 심층 가치 있는 소재 1개를 운영자에게 제안(작성은 하지 않음)

## §5 사람 폴백 (AI 없이 직접 발행)

1. 지난주 소식을 3곳에서 훑는다: GeekNews(news.hada.io) + 공식 블로그 1~2곳(OpenAI·Anthropic 등) + SAP News
2. 눈에 띄는 것 6~9건을 날짜·한 줄·링크로 메모(인용 링크는 원출처로)
3. 그중 3건을 TOP으로 골라 §3 형식대로 md 작성 — 최근 주간 트렌드 기사 1건을 열어 그대로 본뜨면 된다
4. GitHub 웹에서 `app/content/기사/`에 저장 → main에 commit → Actions 초록 확인

한 주 건너뛰어도 사이트는 죽지 않는다. 다음 주에 그 주 것만 발행하면 된다(두 주치 합본 금지 — 창은 항상 직전 7일).

# 인사이트 발행 절차 (AI 프롬프트 겸 사람 절차)

> 이 문서 = 인사이트 기사 발행의 **운영 원천**. 자동 루틴이 죽거나 계정이 바뀌어도
> 이 문서 하나로 재구축·수동 실행이 된다.
> 사용법 ① AI에게: 이 문서 전체를 붙여 넣고 "이 절차대로 오늘 치 발행"이라고 지시.
> 사용법 ② 사람이: §6 사람 폴백 절차를 따라 직접 작성.
> 소재 채택 관문(G1~G3)·출처 등급(A/B/C)·frontmatter 규격 = `../CONTRIBUTING.md`가 원천(값 중복 금지).
> 발행 전 자체 검수 = `기사-검수-하네스.md` §4 체크리스트 전항 T 필수.

## §1 발행 체계 (두 경로)

| 경로 | 실행 | 소재 선정 |
|---|---|---|
| 자동(야간 루틴) | 주 3회 월·수·금 05:00 KST | §2 레인 적합 판정으로 자동 선정(건별 승인 없음) |
| 수동(요청·수시) | 운영자 지시 시 | 관문 통과 후보 2~3개 제시 → 운영자가 1개 픽 |

- **산출량 = 신호가 결정**: 관문·레인 적합 소재가 복수면 복수 편, 0건이면 그 회차 발행 생략. 억지로 채우지 않는다.
- 자동 경로 모델 = 표준 등급(고성능 모델 불필요 — 절차가 판단을 대신한다). 서브에이전트는 리서치 1기 상한.
- 스터디원 요청 소재 = 최우선, 후보 경쟁 생략(관문 판정만). 독자 눈높이 = **요청자 기준**(착수 전 용도 확인).

## §2 주제 레인 (자동 경로의 허용 범위 — AI 관련 한정)

두 축 8레인. 축·레인 간 우선순위 없음 — 회차마다 전체에서 가장 시의성 있는 소재를 고른다.

- 취업·시장 축: ①AI 기업분석(기업 1곳 깊이) ②국내 SI·DX 업계 워치 ③직무·채용 변화 ④AI 산업·시장 거시 동향(⚠주간 트렌드와 중복 주의)
- 활용·실전 축: ⑤에이전트·자동화 실전 ⑥ERP×AI ⑦크리에이티브·미디어(영상·이미지·음성 생성) ⑧프롬프트·워크플로 팁

- 배제 = **재직자 전용 소재**(입사 후에만 유효한 것)만. 취업·스펙 앵글은 유효 소재.
- 새로 뜨는 개념·용어 = 레인과 별개로 상시 허용: ①개념 브리핑(왜 지금 뜨는가) → ②정착 신호(수 주째 지속 언급·실무 채택) 확인 시 심층분석 승격(브리핑→심층은 중복 아님).

## §3 소스 풀 (발견 채널과 인용 출처를 구분)

어그리게이터·뉴스레터 = 발견용으로만. 인용 링크는 반드시 원출처로 바꾼다. 해외(영문) 소스 적극 포함.

**A. 공식·1차 (단정 인용 가능)**: OpenAI News · Anthropic Newsroom · Google DeepMind Blog · Microsoft AI Blog · SAP News(ERP×AI 우대 원천) · 각 도구 공식 문서·릴리스 노트(가격·스펙은 여기서만)

**B. 실사용·커뮤니티 (비단정 인용 — "~라는 평가" 화법)**: Hacker News · Reddit(r/OpenAI·r/ClaudeAI·r/LocalLLaMA·r/artificial) · GitHub Trending·릴리스 · simonwillison.net · 유튜브 실사용 리뷰

**C. 발견 채널 (인용 금지 — 원출처 타고 들어감)**: GeekNews(news.hada.io) · 요즘IT

**D. 벤치마크·데이터 (수치 인용)**: Artificial Analysis · LMArena · Epoch AI

## §4 절차 (순서 고정)

1. **스윕**: §3 소스 풀 순회 + 소재별 자유 보충. 각 소재 = 한 줄 요약·원출처 링크·성격 후보·주제 enum.
2. **관문 판정**: G1(그래서 우리는?)·G2(출처)·G3(성격 무게중심) — 기준은 `../CONTRIBUTING.md` 「소재 선정 기준」. 전부 "예"인 소재만 통과.
3. **중복 확인**: `../app/content/기사/` 기존 제목·소재 대조 + 직전 7일 발행 소재와 주제 중복 금지.
4. **선정**: 자동 경로 = 레인 적합 + 신선도 / 수동 경로 = 후보 2~3개 제시 후 운영자 픽.
5. **성격 판정 = 중요도가 결정**(형식·분량 아님): "현업에서 꼭(또는 알면 매우 좋게) 알아야 한다" 수준 = **심층 분석** — 5요소(①무슨 일 ②왜 지금 ③핵심 개념 해설 ④다른 흐름과의 연관 ⑤SO WHAT) 전부 채운다. 사실 전달+짧은 맥락이면 = **트렌드**. 5요소를 못 채울 소재에 심층 라벨 금지.
6. **작성**: 파일 = `../app/content/기사/YYYY-MM-DD-<작성자>-<슬러그>.md`. frontmatter·서식 = CONTRIBUTING.
   - 분량 = 소재가 결정(강제 범위 없음). 문단 3문장 이하 + 빈 줄.
   - B등급 인용 = 비단정 화법. 링크 전수 접속 확인.
   - 마무리 절 = 「SO WHAT」 — 규격·금지 목록 = `기사-검수-하네스.md` §3(낙관 착지 금지).
   - 카피 = 개조식, AI투·과장 금지. 기사 상호참조 금지(각 기사 독립 완결).
7. **자체 검수**: `기사-검수-하네스.md` §4 전항 T — 특히 사건일=1차 발표일 기준·요약↔본문 수치 일치·마감 지난 정보 배제.
8. **게이트 후 게재**: `cd app` → `npm run validate`·`npm test`·`npm run build` 전부 통과 → **main에 commit·push**(콘텐츠 = main 직행 예외). Actions 초록 확인.

## §5 서식 함정 (빌드·발췌가 깨지는 지점)

| 함정 | 규칙 |
|---|---|
| 볼드 플랭킹 | `**79%**가` = 파싱 실패 → 조사까지 포함 `**79%가**` |
| 이탤릭+한글 | `*"…"*한글` 붙여쓰기 금지 |
| 물결 기간 표기 | `~`는 발췌에서 제거됨 → 기간은 `–`(엔대시) 사용 |

## §6 사람 폴백 (AI 없이 직접 발행)

1. §3의 A·C 소스 3~4곳을 훑어 이번 주 소재 1개를 고른다(§2 레인 안에서)
2. G1~G3 관문을 자문한다 — 하나라도 "아니오"면 다른 소재
3. 기존 기사 목록(사이트 인사이트 탭)과 겹치지 않는지 확인
4. GitHub 웹에서 `app/content/기사/`에 md 작성(형식은 최근 기사 1건을 열어 그대로 본뜬다)
5. main에 commit → Actions 초록 확인 → 사이트에서 표시 확인

주 1편이면 페이지는 유지된다. 0편인 주가 있어도 사이트는 죽지 않는다 — 억지 발행이 더 나쁘다.
